{{/* The gallery wrapper for course-v3. base-theme's version exists to bootstrap nanogallery2: it emits a data-base-url for the JS to build thumbnail URLs from, and an inline script that calls window.initNanogallery2 on load. v3 has neither — image-gallery-item.html renders the server-side and image_gallery_lightbox.ts is a delegated listener that needs no init pass — so both are dead weight here, and the inline script is one more thing a CSP would have to allow. data-base-url is read only by course-v2/assets/js/init_image_galleries_from_markup.ts, which never loads in a v3 bundle, so dropping it is safe. Overriding rather than editing base-theme's copy keeps course-v2 on the original. Online only. Theme precedence is left-to-right, so this beats base-theme in ["course-v3", "base-theme"]. The offline chain is ["base-offline", "course-offline-v3", "course-v3", "base-theme"], where base-offline defines its own copy and outranks everything after it — a course-offline-v3 override would still lose, and base-offline's copy has to stay for the v2 offline chain. Offline-v3 therefore keeps the dead attribute and script, which costs nothing there: the script is already no-op'd by its `if (window.initNanogallery2)` guard, and a file:// package has no CSP to satisfy. (This is why the item shortcode could be overridden from course-v3 but the wrapper cannot — base-offline defines the wrapper and not the item.) */}} {{/* The container is a CSS grid, and the grid spec wraps each contiguous run of child text in an anonymous grid item — skipped only if the run is entirely white space. U+00A0 is not white space for that rule, so a stray non-breaking space between two items becomes a real, empty cell. ocw-studio authoring leaves them behind routinely (a line of nothing but NBSP where a blank line was meant), so the fix belongs here rather than in any one course. Only a gap that contains at least one NBSP is collapsed: ordinary whitespace-only gaps are already ignored by the grid and are left exactly as authored, and text like "Fig.1" inside a caption is untouched because it is not framed by > and <. safeHTML is load-bearing. .Inner arrives as template.HTML; piping it through a string filter degrades it to a plain string, which would then be escaped and the whole gallery would render as visible markup. Same idiom as course-v3/layouts/pages/section.html and partials/icon.html. */}}
